오늘 하루 식단 코치

식단 계획이 자꾸 바뀌는 20~30대 직장인이, 오늘 이미 먹은 양과 오늘 활동 기준으로 남은 하루 식사 범위를 숫자와 전략으로 확인하는 웹 서비스

🎯 P0 4개 + P1 1개
💻 Vercel 배포 · URL 접속
🔑 UPSTAGE_API_KEY (서버만)
🌐 한국어 · 계정 불필요
1 한 줄 정의 ▶
감량·유지·증량을 목표로 하는 20~30대 직장인·대학생이, 오늘 이미 먹은 양과 오늘 활동 기준으로 남은 하루 식사 범위를 숫자와 전략으로 확인하고, 회식·외식처럼 계획이 바뀌는 식사 앞에서도 얼마나 조절할지 판단하도록 돕는 웹 서비스.

← A-1 ⑤ SOLVE 답변 기반

2 타깃 사용자 ▶

누구

20~30대 직장인·대학생
감량·유지·증량을 신경 쓰지만, 회식·외식·간식처럼 식사 계획이 자주 바뀌는 사람

고통 지점

지금까지 먹은 양을 기준으로 "오늘 얼마나 더 먹을 수 있는지", "남은 식사를 어떻게 조절할지" 판단이 어려움

접근성

언어: 한국어
비용: 유료 코칭 없이 간단히
디지털 문해력: 높지 않게 — 음식 이름·양만 문장으로 입력하면 사용 가능

핵심 페르소나

28세 직장인, 오늘 점심 김밥 한 줄 + 아메리카노, 저녁에 팀 회식(삼겹살) 예정되어 있음. 목표: 감량.
3 문제 ▶

오늘 점심·간식까지 먹은 양을 기준으로, 저녁·회식·외식을 앞두고 "오늘 얼마나 더 먹을 수 있는지", "남은 식사를 어떻게 조절할지"를 머릿속으로만 어림짐작해야 해서 판단이 어렵고, 과식하거나 반대로 너무 제한하는 결과를 낳음.

또 하루 식사 후 오늘 총 섭취량을 목표와 비교해 정리하는 것도 번거로움 — 숫자로 보기 전까지 "오늘 얼마나 먹었는지" 감으로만 알고 넘어감.

5 핵심 기능 — P0 / P1 ▶

P0 = 결선 데모 필수 (최대 4개) · P1 = 있으면 더 좋은 것

P0

① 기본 프로필 등록 + 저장

성별·나이·키·체중·목표(감량/유지/증량) 처음 한 번 등록 → localStorage 재접속 시 재입력 안 함, 초기화 버튼 제공

P0

② 오늘 활동 강도 선택 (5단계)

거의 없음 / 낮음 / 보통 / 높음 / 매우 높음 — 운동 소모 칼로리 별도 미입력, 활동 강도에 이미 포함 → 중복 계산 방지

P0

③ 오늘 먹은 음식·양 자연어 입력 → 추정 범위

라면 1개, 삼겹살 200g, 김밥 한 줄 등 자연어로 입력 → 끼니별·전체 추정 칼로리 범위 제시 (추정임을 명시)

P0

④ 오늘 기준 요약 + 식사 전략

목표 섭취칼로리 + 현재 섭취량 + 남은 범위 한눈에 요약 + 식사 전략 제시
• 예정 식사 있으면 → 총 섭취량 예상 + 목표 대비 판단 + 조절 안내
• 예정 식사 없으면 → 남은 칼로리 기준 다음 식사량·메뉴 방향 추천

P1

하루 종료 후 목표 대비 결과 확인

오늘 총 섭취량 vs 목표(감량/유지/증량) 대비 결과를 간단히 확인

6 스킬 매핑 — 계산 vs 해석·전략 ▶
서비스의 역할은 계산층(코드)과 해석·전략층(Solar Pro 4)으로 나눈다.

계산층 · 코드 서버사이드 직접 연산

• BMR (Mifflin-St Jeor, 원값 사용)
• 오늘 활동계수 적용 → 오늘 예상 소비칼로리
• 감량/유지/증량 목표 조정
• 현재 섭취 하한·상한 합계
• 남은 칼로리 범위

해석·전략층 · Solar Pro 4 모델명 solar-pro4 고정

• 자연어 음식·양 해석 (라면 1개, 삼겹살 200g 등)
• 각 음식 추정 칼로리 범위(하한~상한) 산출
• "오늘 전략" 텍스트 생성 (끼니별 균형, 조절 안내 등)
서비스 구조: /api/calculate가 계산층 + Solar 호출을 함께 제공. 클라이언트는 같은 도메인 /api만 fetch. daily-diet-coach의 외부 food API는 없으며, Solar 호출 공개 모델은 Upstage API.
호출 전 안전 점검(A-0) 결과: 목적=오늘 하루 식단 관리 코치 / 필요한 설정=UPSTAGE_API_KEY / 외부 전송=Solar 호출 외 없음 / 권한 요구=없음 → 통과
7 입력 · 출력 ▶
입력 — 기본 프로필 (첫 등록)
  • 성별 (남성/여성)
  • 나이 (세)
  • 키 (cm)
  • 체중 (kg)
  • 목표 (감량/유지/증량)
→
입력 — 오늘 기록 (매일)
  • 활동 강도 5단계
  • 먹은 음식·양 (자연어)
  • 예정 음식 (있으면)
→
출력 — 화면에 보이는 것
  • 목표·현재·남은 칼로리 요약
  • 먹은 음식별 추정 칼로리 기록
  • 예정 식사 분석 (있으면)
  • 오늘 전략 텍스트

저장 방식

저장 대상 저장소 유지 기간 비고
기본 프로필 (성별·나이·키·체중·목표) localStorage 날짜 무관 지속 한 번 등록하면 계속 유지, 초기화 버튼으로 삭제
오늘 활동 강도 localStorage 날짜 기준 (오늘) 같은 날 재접속 시 유지, 날짜 바뀌면 새 기록
오늘 먹은 음식 localStorage 날짜 기준 (오늘) 같은 날 재접속 시 유지, 음식 추가 입력 시 갱신
오늘 예정 음식 localStorage 날짜 기준 (오늘) 없으면 생략 가능
8 필요 설정 ▶

(a) 배포 연결

Vercel 프로젝트 연결 → 프로덕션 도메인: 프로젝트명.vercel.app
환경변수 값은 여기서 안 다룸

(b) 서비스 키 Vercel 환경변수

UPSTAGE_API_KEY
• 용도: Solar Pro 4 호출용 (음식 해석·칼로리 범위·전략 텍스트)
• 발급처: Upstage
• 값은 사용자가 직접 입력, 대화에 적지 않음
• /api만 읽고, 클라이언트에는 0개

(c) 사용자 프로필 + 하루 기록 localStorage

프로필(날짜 무관 지속): gender, age, height_cm, weight_kg, goal
하루 기록(날짜 기준): 오늘 활동 강도, 오늘 먹은 음식(자연어 리스트), 오늘 예정 음식(자연어) — 키: 현재 날짜(YYYY-MM-DD)
• 같은 날 재접속 시 저장돼 있던 오늘 기록 유지
• 날짜가 바뀌면 새 키로 새 하루 기록 시작, 전날은 오늘 화면에 미노출
• 프로필 초기화 버튼은 프로필만 초기화
9 데이터 규칙 ▶
추정치 표시 모든 칼로리 수치·음식 추정치는 활동계수와 일반 음식 참조 정보의 추정치이며 실제 값과 차이 날 수 있음을 표시. 숫자에 "약", 범위에 "~ kcal" 사용, 단정 표현 금지
없는 값 없는 값은 '확인 불가'로 두고 추측하지 않음
키·프록시 주소 서버(/api)에만. 클라이언트(index.html)에는 0개
기준 시각 오늘(date) 기준이라는 점 명시
최소 권한 필요한 계산만 수행

시크릿 창(계정·저장값 없는 첫 방문)에서 아래가 모두 돼야 함

기본 프로필 등록 화면 → localStorage 저장 확인
오늘 활동 강도 + 먹은 음식 입력 → 계산 결과 표시 (목표/현재/남은 칼로리 요약 + 음식별 추정치 + 전략)
예정 음식 입력 시 → 총 섭취량 예상 범위와 목표 대비 판단 표시
예정 음식 없을 때 → 남은 칼로리 기준 식사 추천 표시
같은 날 재접속 시 오늘 활동 강도·먹은 음식 기록 유지

11 제외 범위 ▶
치료식·질환 처방 — 생활 속 칼로리·식사 균형 관리 용도로만. 질환 관리·치료 목적 식단 처방은 하지 않음.
정밀 영양 분석 — 탄단지·미량영양소 등 식사 외 영양 정보는 노출하지 않음. 칼로리 추정·전략만.
실제 소모 칼로리 측정 아님 — 오늘 예상 소비는 활동계수(1.2/1.375/1.55/1.725/1.9) 기반 간이 추정치. 개인별 신체활동·운동 종류·강도·생활패턴에 따라 실제 소비열량과 차이 발생 가능.
운동 소모 칼로리 별도 입력·가산 금지 — 중복 계산 방지. 오늘 활동 강도에 이미 포함.
외부 식품 API 연동 없음 — 일반 음식 참조 범위만 사용. API 키 없음.
