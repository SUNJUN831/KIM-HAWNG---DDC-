오늘 하루 식단 코치

식단 계획이 자꾸 바뀌는 20~30대 직장인이, 오늘 이미 먹은 양과 오늘 활동 기준으로 남은 하루 식사 범위를 숫자와 전략으로 확인하는 웹 서비스

🎯 P0 4개 + P1 1개
💻 Vercel 배포 · URL 접속
🔑 UPSTAGE_API_KEY (서버만)
🌐 한국어 · 계정 불필요
1 한 줄 정의 ▶
오늘 먹은 음식과 활동 상태를 바탕으로 현재 섭취 상태를 분석하고, 남은 하루의 식사 전략과 다음 식사 메뉴를 제안하는 개인 맞춤형 식단 코칭 에이전트.

← A-1 ⑤ SOLVE 답변 기반

2 타깃 사용자 ▶

누구

매번 음식 칼로리를 직접 검색·계산하기 번거로운 사람
오늘 얼마나 먹었는지 간단히 기록하고 확인하고 싶은 사람
남은 칼로리뿐 아니라 다음 식사를 어떻게 구성할지 도움받고 싶은 사람

고통 지점

먹은 음식의 칼로리를 매번 직접 찾아 계산하기 어렵고, 현재까지의 섭취량을 알아도 남은 식사를 어떻게 조절해야 할지 판단하기 어려움
회식·외식처럼 계획이 바뀌거나 감량·유지·증량 목표에 맞춰 식사를 조절해야 할 때 기준이 모호함

접근성

언어: 한국어
비용: 유료 코칭 없이 간단히
디지털 문해력: 높지 않게 — 아침·점심·저녁·간식별로 먹은 음식을 자연어로 입력하면 사용 가능

핵심 페르소나

28세 직장인, 오늘 점심 김밥 한 줄 + 아메리카노, 저녁에 팀 회식(삼겹살) 예정되어 있음. 목표: 감량.
3 문제 ▶

먹은 음식의 칼로리를 매번 직접 찾아 계산하기 어렵고, 현재까지 얼마나 먹었는지도 파악하기 번거로움. 현재까지 섭취량을 알아도 남은 하루에 무엇을 얼마나 먹어야 하는지 판단하기 어렵고, 회식·외식·간식처럼 계획이 바뀌면 기존 식단 계획을 어떻게 조절해야 할지 기준이 모호함.

일반적인 식단 기록 과정에서는 섭취량을 확인한 뒤에도, 그 결과를 다음 식사 행동으로 연결하는 판단을 사용자가 직접 해야 하는 경우가 많음. DDC는 기록 → 상태 분석 → 코칭 → 다음 식사 추천의 흐름으로 이 연결을 돕는 서비스.

서비스 이용 흐름

프로필 등록 → 기록 날짜 선택 → 아침/점심/저녁/간식 입력 → (필요 시) 추가 일정·예정 식사 입력 → 기록 저장 → 상태 분석 및 코칭 확인 → 다음 식사 추천 확인
특정 시간대보다 필요한 순간마다 URL로 접속해 사용하는 흐름. 과거 날짜 기록을 조회해 당시 섭취 상태도 확인할 수 있음.
5 핵심 기능 — P0 / P1 ▶

P0 = 결선 데모 필수 (최대 4개) · P1 = 있으면 더 좋은 것

P0

① 개인 프로필 기반 목표 설정

성별·나이·키·체중·목표(감량/유지/증량) 등록 → localStorage 저장, 재접속 시 유지
오늘 활동 강도 5단계(거의 없음/낮음/보통/높음/매우 높음) 선택 → BMR(Mifflin-St Jeor) + 활동계수 + 목표 조정으로 하루 목표 섭취량 계산
운동 소모 칼로리는 활동 강도에 이미 포함 (별도 입력 불필요)

P0

② 끼니별 자연어 식사 기록 + 현재 상태 분석

아침·점심·저녁·간식 4개 textarea에 먹은 음식을 자연어로 입력 → Solar Pro 4가 각 음식의 추정 칼로리 범위(하한~상한) 산출
끼니별·전체 섭취량 합계 표시 (추정임을 명시)
필요 시 추가 일정·예정 식사 textarea에 입력 가능
현재 섭취 상태 요약: 현재까지 섭취한 칼로리 범위 + 목표 섭취 칼로리 + 남은 칼로리(또는 초과 상태) + 목표 대비 진행도 바

P0

③ DDC 에이전트 코칭 + 다음 식사 추천

Solar Pro 4 에이전트 코칭 3블록 제공:
• 현재 상태 — 현재까지 섭취량과 남은 칼로리를 바탕으로 종합 상태 분석
• 식단 분석 — 오늘 식사 구성의 균형을 살펴봄
• 생활 패턴 반영 — 입력한 추가 일정·예정 식사 등을 고려한 다음 식사 방향 제안
Solar Pro 4 다음 식사 추천 — 현재 섭취 상태와 남은 칼로리를 기준으로 다음 식사 후보 음식 카드 제시 (추천 메뉴별 예상 칼로리와 간단한 설명 포함)

P0

④ 날짜별 기록 관리 + 분석 결과 저장·복원

날짜 선택기로 오늘 또는 과거 날짜 선택 → 해당 날짜 기록으로 전환. 오늘이 기본값
선택한 날짜의 기록 저장(날짜 기준 localStorage) + 초기화 기능
저장 당시의 분석·코칭·추천 결과를 그대로 복원 — 다른 날짜로 이동했다가 돌아오거나 새로고침해도 마지막 저장 결과 유지
저장된 기록을 수정한 뒤 다시 저장하면 최신 입력 기준으로 결과가 갱신됨

6 스킬 매핑 — 계산 vs 해석·전략 ▶
서비스는 입력 → 계산 → 현재 상태 해석 → 코칭 → 다음 식사 추천의 흐름으로 동작한다.

계산층 · 코드 입력 데이터와 규칙을 바탕으로 수치 계산

• 사용자 프로필(성별·나이·키·체중)과 활동 수준을 바탕으로 하루 목표 섭취량 산정 (BMR Mifflin-St Jeor + 활동계수 + 감량/유지/증량 목표 조정)
• 아침·점심·저녁·간식별 섭취량을 집계해 현재 총 섭취량 계산
• 각 끼니의 음식별 칼로리를 하나의 확정값이 아니라 추정 범위로 계산 (하한~상한)
• 목표 대비 남은 칼로리 또는 초과 상태 계산
• 날짜별 저장·복원 처리

해석·전략층 · Solar Pro 4

• 자연어로 입력된 음식·양 해석 (라면 1개, 삼겹살 200g 등)
• 각 음식의 추정 칼로리 범위(하한~상한) 산출
• 현재까지의 섭취 상태를 해석 — 현재 섭취량, 목표 대비 상황, 남은 칼로리 범위를 종합해 설명
• 오늘 식단 구성 분석 — 아침·점심·저녁·간식의 균형과 구성 특징을 살펴봄
• 사용자가 입력한 추가 일정·예정 식사 반영 — 예정 식사 시 총 섭취량 예상과 목표 대비 판단을 함께 생성
• 해석 결과를 바탕으로 남은 하루의 식사 방향 코칭 (현재 상태 / 식단 분석 / 생활 패턴 반영 3블록)
• 현재 상태에 적합한 다음 식사 메뉴 추천 — 추천 후보 음식 카드와 예상 칼로리·간단한 설명 제공
서비스 구조: /api/calculate가 계산층 + Solar 호출을 함께 제공. 클라이언트는 같은 도메인 /api만 fetch. daily-diet-coach의 외부 food API는 없으며, Solar 호출 공개 모델은 Upstage API.
호출 전 안전 점검(A-0) 결과: 목적=오늘 하루 식단 관리 코치 / 필요한 설정=UPSTAGE_API_KEY / 외부 전송=Solar 호출 외 없음 / 권한 요구=없음 → 통과

  • 나이 (세)
  • 키 (cm)
  • 체중 (kg)
  • 목표 (감량/유지/증량)
→

→

  • 오늘 활동 수준 — 5단계 중 선택 (거의 없음 / 낮음 / 보통 / 높음 / 매우 높음)
  • 아침 식사 — 먹은 음식을 자연어로 입력
  • 점심 식사 — 먹은 음식을 자연어로 입력
  • 저녁 식사 — 먹은 음식을 자연어로 입력
  • 간식 — 먹은 음식을 자연어로 입력
  • 추가 일정 또는 예정 식사 — 있으면 자유롭게 입력 (없으면 생략 가능)

식사는 아침·점심·저녁·간식별로 나누어 각 끼니에 먹은 음식을 자연어로 입력하는 방식입니다.

→
출력 — 화면에 보이는 것
  • 음식별 추정 칼로리 범위 — 각 음식의 하한~상한 kcal (예: 약 400~550 kcal)
  • 끼니별 섭취량 — 아침·점심·저녁·간식별 합계 칼로리 범위
  • 현재까지의 총 섭취 칼로리 범위 — 모든 끼니 합산
  • 목표 섭취 칼로리 — 프로필과 활동 수준으로 산정한 하루 목표
  • 남은 칼로리 또는 초과 상태 — 목표 대비 남은 칼로리 범위, 초과 시 초과량 표시
  • 목표 대비 섭취 진행도 — 현재 섭취량의 목표 대비 비율을 진행도 바로 표시
  • DDC 에이전트 코칭 (Solar Pro 4):
    • 현재 상태 — 현재 섭취량과 남은 칼로리를 바탕으로 종합 상태 분석
    • 식단 분석 — 오늘 식사 구성의 균형·특징을 살펴봄
    • 생활 패턴 반영 — 입력한 추가 일정·예정 식사 등을 고려한 다음 식사 방향 제안
  • 다음 식사 추천 (Solar Pro 4):
    • 추천 메뉴 — 현재 상태와 남은 칼로리에 맞는 후보 음식
    • 예상 칼로리 — 추천 메뉴별 예상 칼로리 범위
    • 간단한 설명 — 왜 이 메뉴가 어울리는지 한 줄 설명

저장 방식

저장 대상 저장소 유지 기간 비고
사용자 프로필 (성별·나이·키·체중·목표) localStorage 날짜 무관 지속 한 번 등록하면 재접속 시에도 유지된다. 초기화 버튼으로 삭제 가능
선택한 기록 날짜 브라우저 저장공간 현재 선택 기준 날짜 선택기로 오늘 또는 과거 날짜를 선택한다. 오늘이 기본값이며, 날짜를 변경하면 해당 날짜에 저장된 기록을 불러온다. 저장된 기록이 없는 날짜는 빈 기록으로 시작한다
오늘 활동 수준 (5단계) 브라우저 저장공간 선택한 날짜 기준 같은 날짜를 다시 열면 유지된다. 날짜를 바꾸면 새 기록으로 시작
아침·점심·저녁·간식별 먹은 음식 (자연어 입력) 브라우저 저장공간 선택한 날짜 기준 같은 날짜를 다시 열면 유지된다. 음식을 추가 입력하면 갱신된다
추가 일정·예정 식사 (자연어 입력) 브라우저 저장공간 선택한 날짜 기준 없으면 생략 가능. 같은 날짜를 다시 열면 유지된다
기록 저장 시점의 분석·코칭·추천 결과 브라우저 저장공간 선택한 날짜 기준 기록을 저장하면 그 시점에 생성된 분석 결과, 에이전트 코칭, 다음 식사 추천 결과가 함께 저장된다. 다른 날짜로 이동했다가 다시 해당 날짜로 돌아오면 저장된 결과를 그대로 복원하며, API를 다시 호출하지 않는다. 브라우저를 새로고침해도 저장된 기록과 결과는 유지된다. 저장한 식사 내용을 수정한 뒤 다시 기록 저장을 누르면 최신 입력을 기준으로 분석·추천을 다시 수행하고 기존 결과를 갱신한다
8 필요 설정 ▶

(a) 배포 연결

Vercel을 통해 서비스 배포
프로덕션 주소: 프로젝트명.vercel.app (주소는 나중에 적음)

(b) 서비스 키 Vercel 환경변수

UPSTAGE_API_KEY를 Vercel 환경변수로 설정
음식 해석, 칼로리 추정, 코칭 및 추천에 사용
키 값은 클라이언트에 노출하지 않음

(c) 사용자 데이터 저장

프로필과 날짜별 식사 기록을 브라우저에 저장
저장된 날짜의 분석·코칭·추천 결과도 함께 유지
다시 해당 날짜를 선택하면 마지막 저장 결과를 복원
9 데이터 규칙 ▶
칼로리 표시 음식 칼로리는 하나의 확정값이 아니라 추정 범위로 표시한다. "약", "~ kcal" 등의 표현을 사용해 추정치임을 명확히 하고, 실제 섭취량이나 조리 방식에 따라 차이가 날 수 있음을 전제로 한다.
목표값 계산 목표 섭취 칼로리는 사용자 프로필, 목표(감량/유지/증량), 활동 수준을 바탕으로 계산한 참고값이다. 음식 칼로리 추정치와 목표 칼로리 계산값을 동일한 개념처럼 표현하지 않는다.
입력 기반 분석 사용자가 입력하지 않은 음식, 식사, 일정은 임의로 추가하지 않는다. 해석이 어려운 정보는 단정적으로 만들어내지 않는다.
날짜 기준 분석과 저장은 현재 선택한 기록 날짜를 기준으로 처리한다.
10 성공 기준 — 데모 시나리오 ▶

처음 방문한 사용자가 아래 흐름을 문제없이 완료할 수 있어야 함

기본 프로필 등록 — 성별·나이·키·체중·목표를 입력하고 저장할 수 있음
날짜 선택 및 식사 기록 — 기록할 날짜를 선택하고, 아침·점심·저녁·간식에 먹은 음식을 자연어로 입력할 수 있음
기록 저장 및 칼로리 분석 — 기록 저장 후 음식별·끼니별 추정 칼로리가 표시되고, 현재 섭취량·목표 섭취량·남은 칼로리(또는 초과 상태)와 목표 대비 진행도를 확인할 수 있음
DDC 에이전트 코칭 — 현재 상태, 식단 분석, 생활 패턴 반영 3개 영역의 코칭이 표시됨
다음 식사 추천 — 현재 섭취 상태를 기준으로 추천 메뉴가 표시되고, 추천 메뉴별 예상 칼로리와 설명을 확인할 수 있음
추가 일정·예정 식사 반영 — 추가 일정이나 예정 식사를 입력하면 분석과 코칭에 반영됨
날짜별 기록 복원 — 다른 날짜로 이동한 뒤 다시 저장한 날짜로 돌아오면 해당 날짜의 식사 기록과 마지막 분석·코칭·추천 결과가 그대로 복원됨
기록 수정 및 갱신 — 기존 날짜의 식사 내용을 수정하고 다시 기록 저장하면 최신 입력을 기준으로 분석·코칭·추천 결과가 갱신됨
새로고침 후 유지 — 브라우저를 새로고침해도 저장된 프로필과 날짜별 기록·분석 결과가 유지됨

11 제외 범위 ▶
의료·치료 목적 식단 처방 — 질환 관리, 치료식, 의료적 식단 처방은 제공하지 않음. 일상적인 식사 조절을 돕는 용도로 한정.
정밀 영양 분석 — 탄수화물·단백질·지방, 미량영양소 등 정밀 영양 분석은 제공하지 않음. 현재 MVP는 칼로리 추정과 하루 식사 전략 중심.
